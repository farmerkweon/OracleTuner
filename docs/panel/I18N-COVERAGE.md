### 2-1. 측정 방법과 제외 기준

- `web/js/**` 의 `.js` 18개 파일을 **문자열 상태기계로 토큰화**(주석·정규식 리터럴을 정확히 제거)한 뒤,

## E. 동작 호환성에 관해 밝혀 둘 것

1. **언어 전환 즉시 반영을 위해 모듈 상수를 함수로 바꿨다.**
   `history.js` 의 `STATUS_LABEL`/`VERDICT_LABEL`, `workbench.js` 의 `STAT_NOTES`/`PLAN_METRIC_LABEL`,
   `candidates.js` 의 `GRADE_STYLE.label`/`VERDICT_PILL.text` 는 **모듈 로드 시점에 한 번만 평가되는 상수**였다.
   그대로 `t()` 를 넣으면 로드 시점 언어로 굳어 **언어를 바꿔도 안 바뀐다.**
   → 조회 **함수**(또는 키만 담은 맵)로 바꿔 호출 시점에 번역되게 했다. 표시 스타일(`cls`/`icon`)은 그대로 뒀다.

2. **`t` 이름이 지역 변수에 가려지던 3곳을 리네임했다.**
   `workbench.js` 의 `const t = r.timings` → `tm` (2곳), `history.js` `guessTitle()` 의 `const t = …tables…` → `tables`.
   리네임하지 않고 `t()` 를 넣었으면 **런타임에 "t is not a function" 으로 터졌을 자리**다.

3. **ko 표기가 통일되면서 일부 문구가 미세하게 바뀌었다** (중복 키 통합의 결과, 의도된 변경):
   - 이력 화면 검증 배지: `완전 동일`→`동일`, `집합 동일`→`순서다름`, `결과 다름`→`결과다름`, `비교 불가`→`확인불가`
     (후보 화면에서 쓰던 `verdict.*` 로 통합 — 두 화면이 같은 판정을 다르게 부르던 문제도 같이 해소).

> 일본어 사용자가 [샘플 예제] 버튼을 누른 직후 **가장 먼저 보는 것이 좌측 [SQL 목록]** 인데,
> 이것이 UI 문자열이 아닌 저장 데이터라 앞선 334건 사전화에 잡히지 않아 한국어 그대로였다.

### F-1. 처리 건수

| 대상 | 항목 | 번역한 필드 | 문자열 수 |
|---|---|---|---|
| `demo/02-examples.js` | 예제 8건 | `name`, `desc`, `note`(SQL 앞 설명 주석) | 8×3×4 = **96** |
| `demo/01-setup.sql` | 1건 | `--@ name`, `--@ desc` | 2×4 = **8** |
| `demo/09-drop.sql` | 1건 | `--@ name`, `--@ desc` | 2×4 = **8** |
| 폴더(태그) 이름 | `데모` → `Demo`/`デモ`/`演示` | `DEMO_FOLDER` | 4 |
| `web/js/i18n.js` | `sqls.demoInstalled`·`sqls.demoConfirm` 의 **en/ja/zh 한글 혼입 6건** | — | 6 |
| | | **합계** | **122** (항목 10건 × 4로케일) |

> 마지막 행은 D-1 의 **2번(`DEMO_FOLDER`)이 원인이라고 지목했던 그 6건**이다. 폴더명 정책이 정해지면서 같이 해소됐다.

### F-2. 방식 — 왜 "설치 시점 로케일" 인가

원본에 **ko/en/ja/zh 4벌을 담아 두고, [샘플 예제] 를 누른 시점의 화면 언어로 하나를 골라 저장**한다.

- 고르는 곳: `server/demo-install.js` 의 `localize(item, lang)` / `demoItems(lang)`
- 언어를 싣는 곳: `web/js/views/library.js` → `api.installDemo(getLang())` → `POST /api/snippets/install-demo {lang}`
  (화면 언어는 `localStorage.ot.lang` 에만 있어 서버가 알 수 없다. 없으면 `settings.json` 의 `ui.locale`, 그것도 없으면 `ko`)

**언어를 바꾸면 목록도 따라 바뀌는 방식은 택하지 않았다.** 이유:
스니펫은 **이름이 곧 레코드 키**(파일명 — `snippet-store.safeName`)다. 표시명을 언어에 따라 갈아끼우려면
(a) 저장된 레코드를 리네임하거나 — 사용자가 고친 내용·이름이 날아간다 — (b) 표시명과 키를 분리해야 하는데,
(b)는 저장소·목록·워크벤치 도크·사전까지 번지는 큰 변경이다. 게다가 **데모 스니펫은 사용자가 편집·삭제할 수 있는 데이터**라
사용자가 고친 뒤에도 사전이 이름을 덮어쓰면 오히려 거짓말이 된다. 설치 시점 고정이 이 저장 모델과 맞고,
언어를 바꾼 뒤 다시 [샘플 예제] 를 누르면 그 언어로 다시 깔린다.

### F-3. SQL 본문은 한 글자도 건드리지 않았다

설명 주석을 SQL 문자열 안에 섞어 두면 번역하다 문법·표·컬럼명을 건드릴 위험이 있다.
그래서 주석을 **`note` 필드로 분리**하고 설치할 때 `-- ` 를 붙여 앞에 얹는다 — 번역이 SQL 본문에 **구조적으로 닿을 수 없다.**

```
ko: 4로케일 sql 본문 비교 → 주석 줄 제외 시 완전 동일 (10/10 항목)
```

`--@ name.ja:` 처럼 **로케일 접미사**를 읽도록 `readSqlFile()` 의 메타 정규식을 `(\w+)(?:\.(\w+))?` 로 넓혔다.
`server/api.js` 에 중복돼 있던 `demoItems()` 는 `demo-install.js` 것을 쓰도록 합쳤다(두 벌이 어긋날 자리였다).

### F-4. 검증 — 육안 + 실측

**스크린샷** (`docs/panel/i18n-shots/`) — 4로케일 각각 실제로 [샘플 예제] 버튼을 눌러 설치한 직후의 [SQL 목록]:

| 파일 | 확인한 것 |
|---|---|
| `demo-ko.png` | 폴더 `데모`, 10건 한국어 |
| `demo-en.png` | 폴더 `Demo`, 10건 영어 |
| `demo-ja.png` | 폴더 `デモ`, 10건 일본어. 토스트도 「サンプル 10 件を追加しました。「デモ」フォルダをご確認ください。」 |
| `demo-zh.png` | 폴더 `演示`, 10건 중국어 |

검증용 앱은 **리포에서 직접**(`node server/index.js`, 포트 7072, `ORACLE_TUNER_DATA_DIR` 로 데이터 격리) 띄웠다 —
설치본·포터블 QA 와 겹치지 않게.

**SQL 무손상 실측** — Oracle(도커 `oracle-free`, FREEPDB1/ORAHELPER)에 데모 데이터 30만 건을 만든 뒤,
4로케일로 각각 설치한 예제를 **실제로 실행**:

```

행수도 로케일과 무관하게 동일 (① 8,494 · ② 6 · ③ 8,408 · ④ 8,494 · ⑤ 1,918 · ⑥ 548 · ⑦ 10 · ⑧ 498)
```

## G. QA-SWEEP D04 — 스니펫 이름의 `*` 와 `/` 훼손 (2026-07-31)

> 총괄이 일본어 캡처의 `④ SELECT _ (불필요한 컬럼)` 을 보고 "미번역"으로 의심했는데,
> QA 가 잡은 진짜 원인은 **`SELECT *` 의 `*` 가 `_` 로 바뀐 것**이었다. F절과 같은 영역이라 함께 처리했다.

### G-1. 원인 — 훼손 지점은 딱 한 줄이었다

저장 구조는 **이미 표시명과 저장 키를 나눠 갖고 있었다.**

| 필드 | 뜻 | 쓰이는 곳 |
|---|---|---|
| `name` | **저장 키** | 파일명(`<name>.sql`), URL 경로(`/api/snippets/:name`), 목록 선택·삭제 |
| `title` | **표시명** | 화면에 그리는 이름 (`library.js:159` `text: it.title`, 미리보기 제목, 워크벤치 도크) |

`repo/json-file.js` 는 `--@ name: ${rec.title}` 로 표시명을 따로 적어 두고 읽을 때 되살리며,
`repo/sqlite.js` 도 payload 에 `title` 을 따로 담는다. 화면도 이미 `title` 을 그리고 있었다.

**그런데 `snippet-store.save()` 가 그 `title` 에 깎인 이름을 넣고 있었다:**

```js
const name = safeName(input.name || input.title);
const rec = { title: name, … };   // ← 여기. 원문 대신 새니타이즈 결과가 들어간다
```

`safeName()` 은 윈도우 파일명 금지문자 `\ / : * ? " < > |` 를 `_` 로 바꾼다. 파일명으로는 **반드시 필요한**
처리지만 표시명에까지 적용되어 `SELECT *` → `SELECT _`, `순서/방식` → `순서_방식` 이 됐다.
저장소·화면은 멀쩡했고 **파사드 한 줄이 유일한 훼손 지점**이었다.

### G-2. 고친 방향 — 표시명은 원문 그대로, 키만 안전하게

`server/snippet-store.js` 에 `displayTitle()` 을 두고 `save()` 가 두 값을 따로 만들게 했다.

- `safeName(raw)` → **키**. 기존 규칙 그대로(호환 유지 — 이미 저장된 파일을 찾을 수 있어야 한다)
- `displayTitle(raw)` → **표시명**. `*` `/` 포함 원문 유지. 저장 형식이 `--@ name: …` **한 줄** 헤더라
  제어문자(`\u0000`–`\u001f`)만 공백으로 눕히고 그 외에는 아무것도 바꾸지 않는다

`*` 와 `/` 는 **키에서는 계속 `_` 로 깎인다** — 이게 맞다. 그래야 파일명이 안전하고
`/api/snippets/:name` 경로가 슬래시로 쪼개지지 않는다. 화면에 보이는 것만 원문이면 된다.

### G-3. 검증 — 키와 표시명이 실제로 갈라졌는가

`GET /api/snippets` 로 받은 **키로 열고**(`/api/snippets/:name`) **Oracle 에서 실행**한 실측:

```
OK  key="④ SELECT _（多余的列）"        title="④ SELECT *（多余的列）"        rows=8494
OK  key="⑧ 连接 —— 顺序_方式的竞争"     title="⑧ 连接 —— 顺序/方式的竞争"     rows=498
=== 열기+실행 10 성공 / 0 실패 ===
```

**DOM `textContent` 확인** (QA 가 쓴 것과 같은 증거 유형, `.tree-leaf-name`) — 4로케일 모두:

| 로케일 | ④ 항목 | ⑧ 항목 | 훼손(`SELECT _`) |
|---|---|---|---|
| ko | `④ SELECT * (불필요한 컬럼)` | `⑧ 조인 — 순서/방식 경합` | 없음 |
| en | `④ SELECT * (unneeded columns)` | `⑧ Join — order/method contention` | 없음 |
| ja | `④ SELECT * (不要な列)` | `⑧ 結合 — 順序/方式の競合` | 없음 |
| zh | `④ SELECT *（多余的列）` | `⑧ 连接 —— 顺序/方式的竞争` | 없음 |

스크린샷 `docs/panel/i18n-shots/demo-{ko,en,ja,zh}.png` **재촬영** — 네 장 모두 목록에 **별표가 그대로** 보인다.

**이미 저장된 스니펫**: 훼손된 옛 레코드(`title: '④ SELECT _ …'`)를 심어 두고 재설치해 보니
**키가 같아 같은 파일을 덮어쓰며 표시명만 복구**됐다(중복 생성 없음, 10건 유지). 사용자는 [샘플 예제]를 다시 누르면 된다.

회귀: 리포 테스트 **163 + 4 통과 / 0 실패**.
